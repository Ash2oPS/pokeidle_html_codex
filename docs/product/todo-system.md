# TODO System

## Canonical Files

- [todo-backlog.md](./todo-backlog.md) is the canonical list of open work.
- [../../progress.md](../../progress.md) is the append-only completion log for substantive finished work.
- [../ai/change-workflow.md](../ai/change-workflow.md) carries the required same-change maintenance rule for tracked work.

## Horizons

- `Short term`: current slice-critical work, active blockers, and the next highest-leverage implementations.
- `Medium term`: important follow-ups that matter soon but do not block the current slice.
- `Long term`: post-slice or broad-scope work that should stay visible without crowding active priorities.
- `Watchlist`: debt, risks, cleanup, or validation concerns worth tracking without promising an immediate slot.
- `Parking lot`: ideas intentionally remembered but not committed yet.

## Backlog Item Style

- Keep one bullet per actionable outcome.
- Start items with short area tags in backticks such as `gameplay / slice` or `tooling / ux`.
- Describe the outcome to reach rather than low-level implementation trivia.
- Keep items short and rewrite them when the real goal changes materially.

## Update Workflow

- Add an item as soon as requested or accepted work is not already represented in the backlog.
- Move an item between sections when priority changes instead of duplicating it.
- Remove an item once the work is complete, and log the completion in [../../progress.md](../../progress.md) when the result is substantial enough to keep historical traceability.
- Delete invalid or obsolete items instead of keeping dead backlog noise.
